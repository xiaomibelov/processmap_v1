Целевая среда: https://stage.processmap.ru/ (автодеплой из main через workflow `deploy-stage.yml`).

## 1. Что конкретно изменилось для пользователя

### Новое (и где это искать)

| Что | Где | Кто видит |
|---|---|---|
| Таб **«Генерация тестов»** | Админ-панель → раздел **LLM** (`/admin/llm`), крайний правый таб | Только с правом «API Docs»: platform admin (`is_admin`) **или** роль в активной организации `org_owner` / `org_admin` / `auditor` |
| Карточка **«Генерация API-тестов»** | Внутри таба: выбор тега OpenAPI + размера батча (1–20), кнопка «Запустить генерацию» | То же |
| Карточка **«Активный запуск»** + **«История запусков»** | Там же, под формой | То же |

**Важно про видимость:** у пользователя без права «API Docs» таба «Генерация тестов»
**нет в интерфейсе вообще** — это by design (тот же гейт, что у кнопки «API Docs»
в верхней панели). Если кто-то «потерял» таб — проверить роль в активной
организации (переключение организации меняет видимость!).

### Что НЕ изменилось

- Кнопки «Админ-панель», «API Docs», все существующие табы LLM (Провайдеры, Модели, Промты, Фичи, Расход) — на месте, поведение прежнее.
- Никаких изменений в рабочей области, сессиях, диаграммах, нотификациях.
- Сгенерированные тесты живут только в GitHub (ветки `test/llm-gen-*` + PR) — на продукт не влияют.

### Изменения под капотом (для администратора)

- Новые API-эндпоинты: `POST /api/admin/testgen/run`, `GET /api/admin/testgen/runs[/{id}]` (право = «API Docs»; 401/403 по стандарту, 409 при повторном запуске по тому же тегу).
- Новая таблица БД `testgen_runs` (создаётся автоматически при первом обращении, миграция не нужна).
- Новый CI-workflow `llm-testgen.yml` (только ручной запуск; генератор исполняется в GitHub Actions, **не** на сервере).

## 5. Конфигурация фичи (что будет без неё)

Кнопка «Запустить генерацию» требует настройки. Без неё фича **честно
сообщает об ошибке**, ничего не ломая:

| Состояние | Поведение кнопки |
|---|---|
| Нет `GITHUB_TOKEN`/`GH_PAT` на бэкенде | Ошибка «github_not_configured» (503) |
| Токен есть, но workflow ещё не в main* | Ошибка «github_dispatch_failed» (502), запуск помечается failed, повтор возможен |
| Всё настроено | Запуск queued → running → done + ссылка на PR с тестами (поллинг 12 сек сам обновит) |

\* после мержа #709 workflow уже в main — пункт закрыт.

**Полная настройка (для реального запуска генерации):**
- GitHub → Settings → Secrets: `LLM_TESTGEN_API_KEY`, `LLM_TESTGEN_BASE_URL`
  (опционально Variable `LLM_TESTGEN_MODEL`, default `deepseek-v4-flash`);
- Env бэкенда на стэйдже: `GITHUB_TOKEN` (или `GH_PAT`) с правами `actions:write`
  на репозиторий — добавить в `.env` и `docker compose up -d api`.

## 6. Rollback

Если после деплоя что-то не так:
- **Быстрый**: workflow `deploy-stage-ref` (ручной запуск) с предыдущим sha
  (`31385952977` = main до #709, merge #708) — вернёт состояние до фичи за ~6 мин;
- **Точечный**: фича изолирована (новые файлы + 1 таблица), откат не трогает
  остальной функционал; таблица `testgen_runs` безвредна при откате кода.

## 7. Известные ограничения

- Повторный запуск по тому же тегу, пока активен предыдущий → 409 «уже есть активный запуск» (защита от дублей).
- Падение GitHub API не роняет админку: карточка покажет последний известный статус.
- Белый список тегов фиксирован (39 тегов спеки) — произвольные строки в запуск не принимаются.
