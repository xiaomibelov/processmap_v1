# PLAN — Перерисовка страницы «Анализ процессов»

**Контур:** `feature/analysis-tabs-ux-overhaul`  
**База:** `origin/main` (`0fd01f16`)  
**Срочность:** высокая, но код пишется только после approve этого PLAN.  
**Merge/deploy:** только владелец вручную.

---

## 1. Цель и scope

Сделать так, чтобы страница **«Анализ процессов»** выглядела единообразно и по-современному.

- Перерисовать 4 сабтаба, которые сейчас несут legacy-вёрстку `interviewBlock`:
  1. **Границы**
  2. **Действия** (toolbar + companion-панель)
  3. **Исключения**
  4. **AI**
- Не трогать **Ветки** и **Итоги** — там уже новые компоненты (`VirtualBranchesTable`, `AnalysisKpiCard`).
- Сохранить `ProductActionsPanel` и `RagSearchPanel` в companion-панели «Действия», но вписать их в новую вёрстку.
- Не создавать новых флагов, не добавлять параллельных dashboard, не менять роутинг.

---

## 2. Дизайн: варианты и выбор

| Вариант | Описание | Почему не выбран |
|---------|----------|------------------|
| **A. Горизонтальный степпер + компактные карточки** | START → INTERMEDIATE → FINISH в одну линию, выбор внутри узлов, связующая линия | **Выбран** — лучше заполняет широкий таб, понятен статус |
| B. Вертикальный sidebar-степпер | Метки слева, контент справа | Требует больше места, горизонтальный скролл на узких экранах |
| C. Карточки с прогресс-баром | Три большие карточки с общим прогрессом | Сохраняет проблему «серых плашек», не решает восприятие |

Выбран **вариант A** для Границ. Остальные сабтабы оформляются в единой плотной «аналитической» системе: sticky-заголовки, таблицы с hover, KPI/карточки, скелетоны, доступные empty-states.

## 5. Ключевые технические решения

1. **Нет новых флагов.** Перерисовка in-place: те же компоненты, те же пропсы, другая вёрстка.
2. **CSS-переменные.** Используем существующие `--pm-tobe-*` и `--color-*` из `ProcessAnalysis.module.css`; новые классы добавляем в тот же файл.
3. **Доступность.**
   - Контраст текста ≥ 4.5:1.
   - Видимые `:focus-visible`.
   - Степпер — `role="group"` + `aria-label`.
   - Таблицы — семантические `<table>` с `<caption>`/`<th scope>`.
4. **Производительность.**
   - Ленивый монтаж неактивных табов уже работает через `ProcessAnalysisPage`.
   - `VirtualStepsTable` остаётся.
   - `React.memo` для новых карточек и `AnalysisSection`.
   - Дебаунс поиска/фильтров сохраняем.
5. **Не ломаем.**
   - `ProductActionsPanel` — только обёртка, пропсы не меняем.
   - `RagSearchPanel` — только обёртка.
   - Панель PROCESSMAN, CAS/notes-контуры — не трогаем.
