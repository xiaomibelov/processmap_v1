## 4. Целевая структура страницы «Обзор» (без карточек)

Принцип: секционная страница-сводка. Каждая секция — заголовок с ключевыми числами в тексте/бейджах + компактное содержимое + ссылка-drill-down в профильную вкладку с применённым фильтром.

### 4.1. Шапка контекста
- Человекочитаемое имя объекта среза (сейчас только технический id `ws_..._main`), переключатель среза Workspace / Проект / Сессия.
- Метка «Обновлено: <дата-время последнего ночного расчёта>» + кнопка ручного обновления.

### 4.2. Секция «Схемы» (заменяет плитки «Сводка»)
- В заголовке секции — средние по срезу: **среднее число ТАСОК на схему** и **среднее число ЭЛЕМЕНТОВ на схему**.
  - «Элементы» = все BPMN-элементы (flow nodes: задачи, события, шлюзы, подпроцессы), а не только задачи. Определение фиксируется в отчёте.
  - Средние считаются при ночном пересчёте из BPMN-XML сессий.
- Раскрывающиеся группы (accordion): уровень 1 — проект, уровень 2 — схема/сессия.
  - В строке схемы: таски, элементы, критичные, handoffs, длительность — текстом/бейджами, без карточек/плиток.
  - Строка схемы кликабельна → переход в схему (`/app?session=<id>`).
  - Визуальная сканируемость: выравнивание чисел по колонкам, монотонные строки, сортировка по умолчанию (проект + схема, фиксируется в отчёте).
  - Состояние развёрнутости сохраняется в пределах просмотра (React state, не persist).
- Оставшиеся агрегаты среза (сессий, проектов, свойств, пересчитано, длительность, крит. путь) — одной компактной строкой фактов, не плиткой.
- Секция «Структура» (§4.5 ред. 3) удаляется как дублирующая; её данные переходят сюда.
- Нули не прячем, но подаём нейтрально (empty states, §5).

### 4.3. Секция «Качество данных»
- % задач с заполненным `ee_time`; % с числовым `ingredient_value`; количество строк «нет данных» (случай B из fix-контура).
- Drill-down → вкладка «Свойства» с фильтром по проблемным строкам.

### 4.4. Секция «Требуют внимания»

### 4.5. Переходы

### 4.7. Семантика метрики «критично» (ред. 3, по скрину stage 21/08/26)

Если критерий корректен, но показатель в таком виде неинформативен — не выносить на «Обзор» или заменить производной (например, топ критичных в «Требуют внимания»). Решение зафиксировать в отчёте.

- Состояние сворачивания остаётся доступным в пределах просмотра (React state).

## 5. UI/UX-направление

- **Никаких карточек** — ни KPI, ни навигационных. Секции отделяются заголовками и отступами, не плиткой.
- **Семантика цвета:** цвет = смысл (проблема/норма), не декор.
- **Empty states:** при нулевых значениях — осмысленные нейтральные подписи, не голый 0.
- **Плотность:** страница читается за 5 секунд, помещается в 1–1,5 экрана.
- **Согласованность** с дизайн-системой приложения.
- Адаптивность: 1440px+ основной сценарий, без горизонтального скролла до 1280px.

## 8. Ночной пересчёт (4:30)

- Планировщик: Celery beat — ежедневно в 04:30 Europe/Moscow (конфигурируемо), пересчёт snapshot-агрегатов по всем активным workspace.
- Страница «Обзор» читает только snapshot; «Обновлено» = время snapshot'а.
- Ручная кнопка обновления — тот же пересчёт для текущего среза, с throttle.
- Фейл ночной задачи не роняет страницу: последний успешный snapshot + признак устаревания.

### 8.1. Расчёт без блокировки (изменение норматива п.4 ТЗ от 14/07, решение владельца 21/08/26)

- «Excel с пересчётом» при строках случая B (`ingredient_value` пустое/текст) **больше не блокируется** — выгрузка производится всегда.
- Вместо модалки-блокера — предупреждение со **списком пробелов**:
  - проект → сессия/схема → название task;
  - позиция в схеме: predecessor/successor по sequence flow («между X и Y»); fallback — координаты DI;
  - ссылка-переход к элементу схемы (`/app?session=<id>&element=<bpmn_id>`).
  - Кнопки «Выгрузить» / «Отмена». При подтверждении — стандартная выгрузка Excel.
- В выгрузке строки случая B помечаются `SOURCE = "нет данных"`, `RESULT` пуст — классификация A/B/C не меняется.
- Тот же список пробелов показывается в «Обзоре» (секции «Качество данных» / «Требуют внимания») с теми же ссылками.
- В EXEC_REPORT зафиксировать: норматив п.4 изменён решением владельца от 21/08/26 (для ответа заказчику Mikhaylov A.I.).
