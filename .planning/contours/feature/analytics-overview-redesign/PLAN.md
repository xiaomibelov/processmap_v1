## 4. Целевая структура страницы «Обзор» (без карточек)

Принцип: секционная страница-сводка. Каждая секция — заголовок с ключевыми числами в тексте/бейджах + компактное содержимое + ссылка-drill-down в профильную вкладку с применённым фильтром.

### 4.1. Шапка контекста
- Человекочитаемое имя объекта среза (сейчас только технический id `ws_..._main`), переключатель среза Workspace / Проект / Сессия.
- Метка «Обновлено: <дата-время последнего ночного расчёта>» + кнопка ручного обновления.

### 4.2. Секция «Сводка»
- Одна компактная строка/таблица фактов по срезу (без карточек): действий — N, критично — N, handoffs — N, свойств — N, пересчитано — N, сессий — N, проектов — N, длительность, крит. путь.
- Нули не прячем, но подаём нейтрально (empty states, §5).

### 4.3. Секция «Качество данных»
- % задач с заполненным `ee_time`; % с числовым `ingredient_value`; количество строк «нет данных» (случай B из fix-контура).
- Drill-down → вкладка «Свойства» с фильтром по проблемным строкам.

### 4.4. Секция «Требуют внимания»
- Компактные списки (5–7 строк): топ критичных действий; действия с незаполненными свойствами; открытые вопросы. Ссылки на объекты.

### 4.5. Секция «Структура»
- Проекты и сессии среза: распределение действий по проектам, последние обновлённые сессии — списком/таблицей.

### 4.6. Переходы
- Текстовые ссылки-входы во вкладки «Действия» и «Свойства».

### 4.7. Семантика метрики «критично» (ред. 3, по скрину stage 21/08/26)
- На stage ФК: «критично: 1970» при «действий: 1973» (99,8%) — метрика бессмысленна.
- В рамках контура: разобраться с определением «критично» (критерий слишком широкий? баг классификации?). Если критерий корректен, но показатель в таком виде неинформативен — не выносить на «Обзор» или заменить производной (например, топ критичных в «Требуют внимания»). Решение зафиксировать в отчёте.

## 5. UI/UX-направление

- **Никаких карточек** — ни KPI, ни навигационных. Секции отделяются заголовками и отступами, не плиткой.
- **Семантика цвета:** цвет = смысл (проблема/норма), не декор.
- **Empty states:** при нулевых значениях — осмысленные нейтральные подписи, не голый 0.
- **Плотность:** страница читается за 5 секунд, помещается в 1–1,5 экрана.
- **Согласованность** с дизайн-системой приложения.
- Адаптивность: 1440px+ основной сценарий, без горизонтального скролла до 1280px.

## 8. Ночной пересчёт (4:30)

- Планировщик: Celery beat — ежедневно в 04:30 Europe/Moscow (конфигурируемо), пересчёт snapshot-агрегатов по всем активным workspace.
- Страница «Обзор» читает только snapshot; «Обновлено» = время snapshot'а.
- Ручная кнопка обновления — тот же пересчёт для текущего среза, с throttle.
- Фейл ночной задачи не роняет страницу: последний успешный snapshot + признак устаревания.

## 9. Границы (bounded scope)

**In scope:**
1. Редизайн «Аналитика → Обзор» по §4 (все три среза).
2. Удаление вкладки «Дашборды» по §6.
3. Доработка таблицы «Свойства» по §7 (обязательные пункты 1–2; пункты 3–5 — по решению в отчёте).
4. Ночной пересчёт 4:30 + snapshot-механика по §8.
5. Drill-down-ссылки во вкладки с filter-параметрами.
6. Разбор семантики «критично» по §4.7.

**Out of scope:**
- новые метрики, требующие нового сбора/хранения;
- тренды/дельты/графики за периоды (нет истории — бэклог);
- изменение вкладки «Действия» (кроме приёма filter-параметров);
- fix логики SOURCE (смержен отдельным контуром);
- realtime-обновление в течение дня (кроме ручной кнопки).

## 10. Технические заметки

- Стек: React + i18n (ru.js/en.js — все подписи в оба словаря), FastAPI, Celery + Redis (beat в стеке).
- Данные: существующие endpoints аналитики; при необходимости — один лёгкий aggregate-endpoint для «Качества данных»; snapshot-хранилище — таблица или Redis (выбор зафиксировать в отчёте).
- Drill-down: вкладки принимают query/filter-параметры (`?source=no_data`, `?property=ee_time` и т.п.).
- RBAC: по текущим правам аналитики; при удалении «Дашбордов» права зачистить согласованно.

## 11. Критерии приёмки

1. На «Обзоре» — ни одной карточки; все ключевые существующие данные среза видны в секциях §4.

3. Таблица «Свойства»: заголовки и значения не обрезаны (или есть тултипы); типы свойств структурированы (фильтры/чипы, сортировка, выделение расчётных свойств).
4. Семантика «критично» разобрана, решение зафиксировано в отчёте.
5. Ночная задача отрабатывает в 04:30 (лог/запись), «Обновлено» = последний успешный snapshot; фейл задачи не роняет страницу.
6. Каждая секция «Обзора» ведёт в профильную вкладку с применённым фильтром.
7. Ни одной метрики, которой нет в данных системы; никаких трендов.
8. ru/en словари полные, без хардкода строк.
