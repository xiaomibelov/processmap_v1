# PLAN: Улучшение поиска на Canvas (Schema view)

**Контур:** `feature/canvas-search-improvements`  
**Тип:** `feature`  
**Приоритет:** PREMIUM  
**Роль:** Agent 2 (Executor)  
**Approved:** да — текущий промпт пользователя принят как approved PLAN.  
**Baseline:** `origin/main` (`307effbb8736e354a50a337be445dd3ee2d6b288`)

---

## 1. Контекст

В режиме просмотра схемы (Canvas / Schema view / diagram tab) есть inline-поиск: поле «Поиск по элементам, свойствам...» и переключатели «Элементы» / «Свойства».

**Проблемы:**
- При входе в схему поиск не всегда инициализируется корректно — иногда не реагирует на первый клик/ввод сразу после открытия.
- Текущий UX пассивен: пользователь видит пустое поле и не понимает, что доступно для поиска.

---

## 2. Цели

1. **Instant-список при фокусе:** при клике/фокусе на поле поиска сразу показывать выпадающий список элементов/свойств текущей схемы.
2. **Расширенный поиск:** добавить кнопку/ссылку для открытия панели с фильтрами по всем свойствам и ограниченным списком тасок.
3. **Инициализация при входе в схему:** убедиться, что поиск готов к работе сразу после загрузки диаграммы.

---

## 3. Технический скоуп

**Границы:**
- Только компонент поиска и его data-source.
- Общий layout не трогается.
- Backend: только read-only, миграций не требуется (свойства уже парсятся на клиенте).

## 4. План реализации

### 4.1. Instant-список при фокусе
- Изменить `collectDiagramSearchResults` / `collectDiagramPropertySearchResults` так, чтобы при пустом query можно было получить полный отсортированный список (через флаг `allowEmptyQuery` или отдельную функцию, не ломая существующий контракт).
- Показывать панель результатов в `diagramSearchInlineInput.jsx` независимо от `hasQuery`.
- Ограничить instant-список первыми 10 элементами; добавить ссылку «Показать все...» / скролл.
- Сортировка: по алфавиту (name/title) или по порядку появления на canvas.

### 4.2. Расширенный поиск
- Добавить кнопку/ссылку «Расширенный поиск» рядом с полем или внутри выпадающего списка.
- При клике открывать расширенную панель:
  - Все свойства — фильтры/теги.
  - Таски — первые 5, пагинация или «Показать ещё».
  - Поиск по `name`, `description`, `properties`, `task_id`.

### 4.3. Инициализация при входе в схему
- Проверить, что `refreshElements` / `refreshProperties` вызываются после готовности canvas (`modelerReadyRef` / `viewerReadyRef`).
- Убедиться, что `input` не `disabled` во время загрузки.
- Проверить debounce: первый ввод не должен теряться.

### 4.4. Тесты
- Обновить/добавить unit-тесты для нового поведения пустого query.
- Проверить, что существующий `Ctrl+F` / глобальный поиск не сломан.

---

## 5. Критерии приёмки

- [ ] При клике на поле поиска (пустое) — список элементов/свойств схемы появляется в течение 200 мс.
- [ ] Переключение вкладок «Элементы» ↔ «Свойства» — мгновенное, без перезапроса на сервер.
- [ ] «Расширенный поиск» открывает панель со всеми свойствами и 5 тасками.
- [ ] Поиск работает с первого ввода после захода в схему.
- [ ] Мобильная адаптивность: выпадающий список не выходит за границы viewport.
- [ ] Нет регрессии: существующий поиск по `Ctrl+K`, `Ctrl+F` и глобальный поиск не сломан.

---

## 6. Риски и ограничения

- Изменение поведения при пустом query может затронуть существующие тесты `searchContract.test.mjs`.
- Нужно сохранить backward compatibility для `collectDiagramSearchResults` (contract test ожидает `[]` при пустом query).
- Расширенный поиск по `description` / `task_id` может потребовать расширения `listSearchableElements` в `BpmnStage.jsx`.
