## 2. Диагностика «до» (глазами, по скриншотам в evidence/ux-before/)

### Д1. Главная боль: первый экран — не про главное (визуальная иерархия, F-паттерн)
Порядок секций фактический: **Feature Flags** (занимает весь первый вьюпорт, 11 карточек ≈ 2,5 экрана) → **Recent Audit** → **Карта возможностей** + правая колонка (Сигналы + Система). Ради чего страница существует (карта возможностей + живые сигналы) — ниже сгиба; первый экран показывает метаданные администрирования. Это прямо перекликается с исходной жалобой владельца («не видно основного функционала системы»).

### Д2. Каталог флагов: низкая плотность при высокой функциональной важности (density 8/10 профилю противоречит)
Каждый флаг — full-width карточка с 3-строчным описанием + owner-контур + критерием снятия; toggle слева, maturity-бейдж справа на краю карточки — строка «размазана», взгляд ходит по диагонали. 11 флагов = 2,5 экрана. Описание/владелец/критерий нужны редко (при снятии/аудите), но занимают место всегда.

### Д3. Дисбаланс колонок и потерянная «Система»
Правая колонка (Сигналы + Система) короче левой (карта) в разы; «Система» (инфраструктурные факты) живёт на дне правой колонки и не видна до конца скролла.

### Д4. Recent Audit: сырой hex-id actor'а (`d1a4751e90a1…`) — визуальный шум
Таблица Action/Status/Actor/Time с длинными hex в колонке Actor; строки «login ok» без контекста.

### Д5. Мелочи
- Шапка шелла: combobox контекста обрезан кнопкой «Открыть рабочую область» (на 1440 и 1280) — **это общий шелл AdminApp, вне скоупа страницы** → рекомендация отдельным контуром, здесь не правим.
- Ссылки «Открыть →» в каждой строке карты (7 доменов × строки) — повторяющийся шум; бейджи разной ширины рвут ритм строк.

### Что хорошо (не трогаем)
Сама модель (7 доменов/36 строк, аккордеон, семантика статусов, «Сигналов нет»), сетка без h-scroll на 1280/1440, бейджи зрелости, optimistic toggle с откатом. Состав данных и API — без изменений.

## 3. Варианты компоновки (brainstorming, 3 шт.)

### Вариант 1 — «Сначала сигналы и карта» (рекомендую)

```
[H1 Сводка + бейджи раздела/маршрута/доступа]
[Требует реакции]  full-width slim-плашка: сигналы есть → список kind(count) → href;
                   нет → одна строка «Сигналов нет» (низкий визуальный вес)
[Система]          полоса фактов (как сейчас: Redis · Очередь · Сессии · Проекты · Save latency · Сгенерировано)
[ Возможности системы (2/3)   | Feature Flags (1/3)         ]
[ аккордеон 7 доменов,        | компактный каталог:         ]
[ строки выровнены колонками: | группа-заголовок + строки   ]
[ name | status-badge | fact | (toggle | name+maturity | ›)  ]
[ | «Открыть» у правого края  | описание/owner/removal —    ]
[                             | раскрытие строки по клику   ]
[ Recent Audit ]  full-width внизу, actor → email/короткий id
```

Обоснование (ui-ux-pro-max): F-паттерн — ценность и call-to-action первым экраном; density 8/10 — карта и флаги рядом, без воздушных карточек; progressive disclosure для редких полей флага; «Система» — полосой сразу под сигналами (инфраструктурный контекст виден сразу); Recent Audit — вспомогательный, внизу.
Trade-off: описания флагов прячутся за клик (для админ-инструмента приемлемо; toggle и maturity — всегда видны).

### Вариант 2 — «Карточки доменов» (bento-lite)

```
[Сводка + бейджи]
[Требует реакции slim] [Система strip]
[Карта: сетка 2×4 карточек-доменов]
[ Канвас        ] [ Workspace ] [ AI/LLM   ] [ RAG ]
[ 8 строк: ✓5 ⚪2 ] [ 3 строк    ] [ 7 строк  ] [ 5 ] ...
[ карточка = заголовок + сводка статусов + top-3 строки;
  клик → раскрытие полного списка строк ]
[Feature Flags] [Recent Audit]   (внизу, 2 колонки)
```

Обоснование: визуально «свежее», хорошая сканируемость на уровне доменов.
Trade-off: до большинства из 36 строк — два клика; противоречит density-профилю (8/10) и цели «видеть основной функционал»; больше работы и рисков. Не рекомендую как первую итерацию.

### Вариант 3 — «Минимальная перестановка» (low-risk)

```
[H1 + бейджи]
[Карта + (Сигналы/Система)]   ← secondary→primary, как сейчас свёрстано
[Feature Flags]               ← внизу; карточки → 2-колоночная сетка ≥1440
[Recent Audit]
```

Обоснование: минимальный diff, решает главную боль (первый экран). Trade-off: плотность флагов и дисбаланс колонок остаются; Recent Audit всё ещё выше карты? — нет, ниже. Подходит, если нужно быстро.

## 4. Рекомендация

**Вариант 1.** Закрывает жалобу владельца (первый экран = сигналы + карта), приводит плотность к профилю design-system (8/10), сохраняет всю функциональную модель и данные. Вариант 3 — запасной, если владелец хочет минимальных изменений.

6. Тесты: обновить RTL-тесты затронутых компонентов при смене разметки (обоснование в коммите); smoke и контракты не меняются. Прогоны: `npm test` (дельта падений 0), `npm run build`, скриншоты после на 1440/1280 ru/en — в `evidence/ux-after/`.

Вне скоупа (рекомендации): шапка-шелл (обрезанный combobox) — отдельный контур; en-локаль остального каркаса админки — отдельный контур.
