# RISKS: топ-риски декомпозиции WorkspaceExplorer.jsx

Для каждого риска — как шаг плана (DECOMP.md) его обходит. Уровень: высокий/средний/низкий — вероятность × ущерб именно при механическом переносе.

## R1. Двойное мутабельное хранилище и ручной optimistic rollback — ВЫСОКИЙ

`patchExplorerItemInCaches` (2643) и `handleSaveAssignee` (2976) атомарно пишут в react-query cache И в `treeStateByContext.childItemsByFolder`, rollback откатывает оба по снапшоту. `handleSaveProjectSessionAssignees` (4439) — три хранилища. При расщеплении владелец tree state уезжает в `useTreeExpansion` (Ш12), а патч-логика — в хуки действий (Ш15): если разнести их в разные PR без согласованного интерфейса, промежуточные состояния дадут рассинхрон, который characterization-тесты C3 поймают только если они уже зелёные.
**Обход:** порядок фиксирован — Ш12 до Ш15; хуки действий принимают set-функции tree state пропсами; перенос построчный, включая снапшот-логику; C3 (TESTS-BASELINE 4.3) стоит до обоих.

## R2. Неявный порядок эффектов дерева — ВЫСОКИЙ

Цепочка: attach prefs→saver (2540) → mergedExpanded merge (2558, прецеденс fallback→prefs→explicit) → pref-restore (3206) → bulk apply (3220), оба дёргают `ensureFolderChildrenLoaded` с дедупом через inFlight Set и `loadingByFolder`. В прошлом здесь уже были infinite re-render (#891) и гонки (#891/#893). React гарантирует порядок эффектов внутри компонента, но НЕ между отдельными хуками, если их вызывать в другом порядке.
**Обход:** Ш12a/Ш12b сохраняют порядок вызовов хуков ровно как порядок исходных блоков (вызовы идут на тех же местах тела контейнера); merge-прецеденс переносится без реордеринга; C2 (4.2) фиксирует one-shot restore и дедуп загрузок до Ш12.

## R3. `treeSaverRef` — side-effect в render body — СРЕДНИЙ

Создание saver (2527–2539) с guard `if (!ref.current)` мутирует ref и дергает `setPersistTick` из `onSnapshot` во время рендера. Прямой перенос в тело хука без изменений сохранит работу, но при будущем StrictMode/concurrent — латентный баг; изменение же поведения запрещено границей.
**Обход:** Ш12a заменяет на lazy-init `useState(() => createExplorerTreeSaver(...))` — семантически идентично guard'у (оба создают инстанс один раз), зафиксировано в плане как единственное исключение-«не-перенос». Если владелец сочтёт это нарушением границы — альтернатива: перенос verbatim, отдельный fix-контур на lazy-init.

## R4. Source-тесты пинят текст файла — ВЫСОКИЙ (вероятность ~100% на первом же шаге)

~20 `*.source.test.mjs` делают `readFileSync(WorkspaceExplorer.jsx)` и regex-матчат подстроки. Любой перенос кода ломает их — вплоть до невозможности мержа Ш1.
**Обход:** ретаргет в Ш0 (TESTS-BASELINE 4.5) до первого переноса; матчер смотрит объединённый текст целевых файлов, отсутствующие пути игнорируются. Риск остаточный: ревьюер ретаргета должен проверить, что ни один regex не завязан на порядок следования строк (на порядок завязаны считанные единицы — проверить вручную, список в TESTS-BASELINE §2).

## R5. Порталы и sidebar-регистрации завязаны на порядок хуков и DOM — СРЕДНИЙ

Порталы header'ов (3522/4833) и регистрации sidebar-блоков (3351/3362/4744/4748) обязаны исполняться до early return (4755) и до размонтирования; ExplorerPane подавляет портал при открытом проекте (3312, 5179). Регистрационные хуки живут в середине тела контейнера — при выносе соседних хуков легко случайно переставить их относительно early return.
**Обход:** регистрации переносятся последними, в Ш17 (контейнер), вместе с рендером; до этого они остаются на местах. smoke-тест и `navZonePartA.source.test.mjs` — страховка присутствия строк.

## R6. Merge-order конфликты с живой разработкой — СРЕДНИЙ

Декомпозиция — ~24 PR к одному файлу. Любой параллельный продуктовый контур, трогающий `WorkspaceExplorer.jsx` (а это все workspace-контуры), будет конфликтовать; rebase-цепочка 24 PR — сама по себе источник ошибок.
**Обход:** точки остановления (после Ш8/Ш11/Ш16) позволяют синхронизировать main между волнами; параллельно с продуктовыми контурами декомпозиция не ведётся (договорённость с владельцем); при конфликте приоритет — продуктовый контур, декомпозиция ребейзится. Альтернатива, если темп разработки высокий: «большой взрыв» из 2–3 PR вместо 24 — осознанно против критерия ревьюибельности, решает владелец.

## R7. Переименования/коллизии при импортах — НИЗКИЙ

Целевые имена файлов могут коллизировать с существующими sibling-модулями (`explorerTableFormat.js`, `explorerColumnVisibility.js` уже есть); внутрифайловые имена (например, `Modal`) могут дублироваться с глобальными.
**Обход:** имена целевых файлов зафиксированы в DECOMP.md и проверены на отсутствие в `features/explorer/`; при исполнении первый шаг каждого PR — `npm run lint` (no-undef) + сборка, ловят коллизии до ревью.

## R8. Хрупкие осознанные workaround'ы потеряют контекст — СРЕДНИЙ

(а) Эффект 866 `StatusPopoverControl` с eslint-disable exhaustive-deps (намеренно опускает `state.saving`); (б) guard-комментарии 3350/4743 «хуки до early return»; (в) комментарии о merge-прецеденсе в 2558/3166–3177. Перенос без комментариев = потеря защиты от «исправления».
**Обход:** правило переноса: комментарии и eslint-disable директивы переносятся вместе с кодом построчно, включая «выглядящие устаревшими» — ревьюер каждого шага проверяет наличие директив по чек-листу из REPORT §1.2/§5.

## R9. Pre-existing нарушения «прилипнут» к новым файлам — НИЗКИЙ

`window.confirm` (L4082) уедет с `SessionRow` в `ProjectSessionRows.jsx`, мёртвый импорт (L62) — куда-нибудь в хук. Ревьюеры новых файлов могут принять их за новый код.
**Обход:** явная фиксация в REPORT §5 и DECOMP «out of scope»; в PR каждого шага — пометка «перенесено как есть, fix-контур отдельно»; fix-контуры на confirm/eagerTree/мёртвые пропсы заводятся независимо и мержатся ДО соответствующих шагов, если владелец хочет чистый перенос.

## R10. Верификационный шум среды — СРЕДНИЙ (операционный)

История контура: baseline `npm test` перманентно красный (62–83 pre-existing failures), локально периодически нет node/docker (#890 шёл без прогона тестов, #899 — с заблокированным набором). Декомпозиция из 24 PR без исполняемой страховки превратится в серию «перенёс и надеюсь».
**Обход:** Ш0 обязателен и включает фиксацию failure-set (TESTS-BASELINE §5); CI не запускает тесты — поэтому локальный прогон `npm run test:char` + smoke + source-тестов является gate'ом каждого PR, фиксируется в EXEC_REPORT каждого шага. Без рабочего JS-runtime Ш0 = BLOCKED (честно зафиксировано в TESTS-BASELINE §5).
