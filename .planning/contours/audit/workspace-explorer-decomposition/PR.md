# PR: audit/workspace-explorer-decomposition

## Что

Аудит `frontend/src/features/explorer/WorkspaceExplorer.jsx` перед декомпозицией: инвентаризация ответственностей, карта связанности, метрики, план пошаговой декомпозиции, аудит тестового покрытия и characterization-план, риски. **Только документы — product code не изменён (0 строк кода).**

## Почему

Файл — самый перегруженный в frontend'е: **5204 строки** (вводные «1700+» устарели), 77 top-level определений, 70 `useState`, 28 `useEffect`, два контейнера сложностью 83 и 64 (`ExplorerPane`, `ProjectPane`). Последние пять контуров (#891, #892/#893, #895, #896, #899/#900) чинили следствия в одних и тех же зонах: assignees (4 контура, 2 раунда хотфиксов), состояние раскрытия дерева (infinite re-render, гонки, полные reload'ы), строки над таблицей (3 перекраивания за 3 дня). Это аудит причины.

## Артефакты (все в `.planning/contours/audit/workspace-explorer-decomposition/`)

- **REPORT.md** — инвентаризация: все состояния/эффекты/обработчики/рендер-секции с номерами строк; карта связанности (импорты, единственный importer — ProcessStage.jsx:11; дублирование ExplorerPane↔ProjectPane; prop drilling); метрики (LOC 4902, top-10 сложности, 70/28/29/34 состояний/эффектов/мемо/колбэков); история «где трещал» по артефактам контуров; evidence (`cyclo.py`, полный вывод на 457 функций).
- **DECOMP.md** — главный артефакт: целевая структура (контейнеры + ~15 компонентов + 14 хуков + чистые модули) и **18 шагов + Ш0 + опциональный Ш15′**, порядок «от листьев к корню», каждый шаг — «перенести, не переписать», ~24 PR по ≤ ~400 строк diff, явные точки остановления после Ш8/Ш11/Ш16, out-of-scope список.
- **TESTS-BASELINE.md** — покрытие сейчас: 1 smoke-тест поведенчески, ~20 source-regex тестов, 0 CI-исполнения тестов на PR; пробелы; план characterization-тестов (C1–C4, 16 тестов) + ретаргет source-тестов до первого переноса.
- **RISKS.md** — 10 рисков с уровнями и привязкой к шагам обхода (dual-store rollback, порядок эффектов дерева, source-тесты, merge-order 24 PR и др.).

## Ключевые выводы

1. Файл — «всё, что не влезло в sibling-модели»: чистая логика уже вынесена (~15 модулей), в JSX остались контейнеры, компоненты и обвязка. Декомпозиция — механическая, без архитектурных решений.
2. Самый рискованный узел — optimistic-патч двух-трёх хранилищ с ручным rollback (assignees): переносится строго после вынесения tree state, под characterization-тестами.
3. Вторая зона риска — порядок эффектов дерева и merge-прецеденс fallback→prefs→explicit: перенос без реордеринга, эталоны в C2.
4. Без Ш0 (страховочная сеть + ретаргет source-тестов) первый же перенос сломает ~20 source-тестов и пойдёт вслепую.
5. В CI тесты frontend не исполняются вообще — локальный gate каждого шага обязателен и зафиксирован в плане.
