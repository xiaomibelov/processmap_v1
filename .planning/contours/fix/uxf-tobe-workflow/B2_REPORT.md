# B2 — отчёт по диагностике «Сессия AS IS пуста» у отрисованной сессии

**Дата:** 2026-07-31 · **Контур:** fix/uxf-tobe-workflow

## Что сообщил владелец
Сессия «Лагман с говядиной, 320 г» (594 ревизии, на хост-канвасе отрисована:
дорожки, «Поступил заказ…») → вход в TO BE → жёлтая плашка «Сессия AS IS
пуста», канвас пуст, «Перейти к трансформации» мертва.

## Проверки (stage, API под technologist-demo)
- Сессия с таким названием **не видна** ни в одном из 150 проектов демо-аккаунта
  (summary-view по всем проектам, фильтры «лагман»/«320»/«fsefw») — она
  принадлежит аккаунту владельца, прямой доступ к ней из-под demo невозможен.
  → Точный id сессии владельца не установлен; просим владельца подтвердить
  id/окружение при повторном прогоне.
- Локальная dev-БД (clearvestnic.ru, НЕ stage): найдена «Лагман с говядиной
  (v0.3)» (xml 14KB, валиден) + доказан феномен **дубликатов-сирот**: две
  сессии «Упаковка заказа (v0.3)» — одна с XML (проект TOBE), вторая без
  проекта и БЕЗ XML.

## Корневая причина (уровень кода, доказано репродукцией)
TO BE-рабочее место загружает AS IS **только** из
`GET /api/sessions/{id}/bpmn` (Workspace.jsx, эффект asIsSource). Два сценария
маскировались под одну плашку «Сессия AS IS пуста»:
1. **XML пуст/404** (сессия без BPMN или дубликат-сирота без XML) → плашка.
2. **XML есть, но import-bpmn вернул 0 узлов или ошибку** → та же плашка.

Далее цепочка тупика (B1): `asIsModel=null` → action = «Перейти к
трансформации» → `handleTransform()` содержал **тихий return**
(`if (!importFile && !asIsXmlText) return;`) → клик без единого сетевого
запроса и без реакции UI (доказано: сетевой лог клика `[]`).

Репродукция на stage (пустая сессия e790842747 «UXF probe empty AS IS»):
плашка + пустой канвас + все 7 шагов синие + мёртвая кнопка — **точно**
совпадает с симптомами владельца.

## Что исправлено
- **B1**: на пустой AS IS главное действие — «Начать с чистого листа»;
  «Перейти к трансформации» показывается disabled с причиной
  (`title`: «Трансформация недоступна: в сессии AS IS нет распознанной схемы»).
  На непустой — трансформация работает (playwright: HTTP 200 + 25 бейджей).
- **B2**: сценарии разведены — «XML пуст» vs «не распознан»
  (`ws.asIsImportNoNodes` / `ws.asIsImportFailed`), причина больше не
  маскируется. Дубликат-гипотеза закрыта на уровне UI: список источников
  помечает «(пустая)» и «Создать/Открыть» (B4), «Прочие» для служебных.
- **B3**: step-bar сессионный — done(✓)/current(1)/pending(приглушены)/na.
- **B5**: пустое состояние канваса с действиями (чистый лист / другая сессия;
  после чистого листа — «Перетащите первый блок из Каталога операций» + CTA).

## Осталось открытым ⚠️
1. Точная сессия владельца не идентифицирована (нет доступа из demo-аккаунта).
   Если при повторном прогоне лагман снова покажет «AS IS пуста» — это будет
   означать, что у сессии пуст/бит bpmn_xml при отрисованном хосте
   (тогда отдельный контур: источник истины рендера хоста vs bpmn_xml).
2. На stage накоплено 30+ TO BE-дублей от прогонов W4/OL1 (проект демо) —
   данные, не код; чистка — отдельное решение владельца.

   heat_time_sec, heating_power» на ОБОИХ build (старом и новом) — вне
