## Часть 4 — рекомендации (не кодить)

### 4.1 Мастер-визард «Новый процесс» — целевое состояние, трудоёмкость L
Единый проводник Импорт → Трансформация → Конструктор → Рецепт → Проверка → Публикация → Пилот
с персистентным прогрессом (state в БД или sessionStorage) и возвратом «у вас черновик на шаге 4».
Максимальный UX-выигрыш, но L (новая сущность, маршрутизация, восстановление состояния, тесты).

### 4.2 Минимальная альтернатива (рекомендуется первым шагом), трудоёмкость M
- Статус-бар из 7 шагов на экранах technologist (общий компонент, подсветка текущего).
- Кнопка «Следующий шаг →» в контексте каждого экрана:
  Импорт → «К трансформации» (G1); Трансформация → «В конструктор» (есть); Конструктор (после save) → «К рецепту» (G6);
  Рецепт (после publish) → «К пилоту» (G7); Проверка/публикация — встроены.
- Пустые состояния с кнопкой первого действия (G5, G8).
Закрывает G1, G2, G5–G8 — 80% выигрыша за ~20% стоимости визарда. Без новых сущностей в БД.

### 4.3 Доступ импорта технологу
Сейчас импорт/трансформация/публикация — analyst/admin (require_role). Вопрос владельцу:
**вариант A (проще):** технолог = analyst в контуре технолога (как сейчас d.belov), без новой роли;
**вариант B:** завести роль technologist с правами на импорт (read-последствия) — L по аудиту прав.
Рекомендация: A на горизонте MVP-итерации, B — в v1.

### 4.4 Главный экран технолога (M, часть G4)
«Мои процессы»: карточки шаблонов (статус: черновик/опубликован), рецептов (черновик/published v),
пилотов (прогресс критериев) + кнопка «Новый процесс из AS IS». Данные уже отдают существующие API
(process-templates, recipes, sku-bindings) — только фронт.

### 4.5 Обучение в UI (S)
Пустые состояния с первым действием (в составе 4.2), ссылка «Инструкция» в топбаре technologist-раздела,
тултипы к техтерминам (G10). Онбординг-тур — НЕ делать (дорого, быстро устаревает).
