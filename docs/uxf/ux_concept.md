# UXF — UX-концепт рабочего места технолога (на согласование)

**Статус:** DRAFT v1, требует апрува владельца ДО реализации (Блок 2).
**Дисциплина:** ui-ux-pro-max — приоритеты: доступность/обратная связь →
иерархия действий → состояния → токены → визуальная полировка.
**Контекст:** прогон владельца 2026-07-31 застопорился: «хаос и мало
действий по to be». Блок 1 (баги B1–B5) уже исправлен (коммит 42cf6d58);
этот документ — пересборка UX поверх починенного фундамента.

## 1. Роли и режимы экрана /app

У экрана две аудитории с разными задачами:

| | Режим «Схема» (AS IS) | Режим «TO BE» (рабочее место) |
|---|---|---|
| Роль | аналитик, редактор | технолог |
| Задача | моделировать/обсуждать текущий процесс | построить и опубликовать TO BE |
| Канвас | bpmn.io (версии, XML/DOC/DOD, экспорты) | GraphCanvas overlay (OL1) |
| Панели | палитра BPMN, Свойства, Аналитика, Обсуждения | шаги воркфлоу, параметры блока, решения, рецепт, проверка, публикация, пилот |

**Принцип 1. Явное переключение одним контролом.** В шапке — сегментированный
переключатель «Схема | TO BE» (не пассивный аккордеон в сайдбаре). Состояние
переключателя всегда видно; возврат в «Схему» — 1 клик (сейчас: «← К сессии»).
Никаких трёх ролей на одном экране одновременно.

**Принцип 2. В TO BE-режиме аналитические элементы СКРЫТЫ, а не свёрнуты.**
Убираются с экрана: панель вкладок хоста (Diagram/XML/DOC/DOD/Аналитика),
bpmn.io-палитра и «Свойства» (Collaboration, in/out, robot), Обсуждения,
Экспорты. Остаются: step-bar, тулбар рабочего места, overlay-канвас,
правая панель воркфлоу, левая панель (см. §4). Это не удаление функций —
они доступны в режиме «Схема» в 1 клик.

## 2. Иерархия действий

**Принцип 3. На каждом шаге — ОДНО главное действие (primary).** Остальное —
вторичное (обычные кнопки) или в панель. Уже заложено в Блоке 1 (action-модель
`Workspace`): на каждом состоянии ровно один `ws-action` primary. Доводка:
вторичные действия визуально отделить (группа справа), primary — слева и
всегда согласован с текущим шагом step-bar'а (подсветка связи
«шаг ↔ действие» одинаковым акцентом).

| Шаг | Primary | Вторичное |
|---|---|---|
| Импорт AS IS | «Перейти к трансформации» (или «Начать с чистого листа» при пустой) | «Выбрать другую сессию» |
| Трансформация | решения в панели; далее «Сохранить» | accept/reject по одному |
| Конструктор | «Сохранить» | Связать, Каталог, палитра |
| Рецепт | «Сохранить рецепт» | параметры |
| Проверка | «Проверить» | замечания |
| Публикация | «Опубликовать» | версии |
| Пилот | «Создать пилот» | критерии |

**Принцип 4. Step-bar как карта, а не гирлянда.** Уже в Блоке 1:
пройденные ✓ (зелёные), текущий (1, акцент), недоступные приглушены,
«не требуется» — na. Доводка: причина недоступности при наведении
(сейчас — check-текст в title; сделать читабельный tooltip с действием:
«сначала сохраните шаблон»).

## 3. Точка входа TO BE из режима «Схема»

**Принцип 5. Одно главное действие от текущей схемы.** На экране «Схема»
(когда у текущей сессии есть BPMN) — кнопка в шапке/тулбаре:
- TO BE не существует → «Создать TO BE»;
- существует → «Открыть TO BE» (ведёт в рабочее место с этой AS IS).
Вторичное (меню «…» или под кнопкой): «TO BE из другой сессии проекта»
(список с человеческими именами — уже отфильтрован в Блоке 1, B4) и
«TO BE с чистого листа». Аккордеон-список из 6+ пунктов с мусором как
главный вход — уходит (остаётся в сайдбаре как вторичный путь).

## 4. Левый сайдбар в TO BE-режиме

**Принцип 6. Язык воркфлоу, а не язык хоста.** В TO BE-режиме левая панель:
1. «Назад к схеме» (возврат);
2. контекст: «TO BE из «Лагман…»» (источник, статус черновика);
3. шаги воркфлоу (компактный список с состояниями — зеркало step-bar);
4. замечания/история (после публикации).
НЕ показываются: «Свойства» bpmn.io (Collaboration, in/out, robot),
«Пути и последовательность», «Execution Bridge», «AI-вопросы» и прочие
аналитические секции хоста.

## 5. Состояния экранов (по дисциплине: из каждого состояния есть действие)

| Экран | Пустое | Загрузка | Ошибка | Успех |
|---|---|---|---|---|
| Точка входа | нет сессий → «С чистого листа» | skeleton кнопки | toast + retry | «Создать/Открыть TO BE» |
| Рабочее место, AS IS пуста | ✅ Блок 1: выбор чистый лист/другая сессия | спиннер поверх канваса | причина + действие (уже: разведены «пуста»/«не распознана») | overlay + текущий шаг |
| Канвас чистого листа | ✅ Блок 1: приглашение + CTA каталога | — | — | первый блок → шаг «Конструктор» |
| Трансформация | «Начать с чистого листа» | индикатор на кнопке | toast с причиной, кнопка снова активна | бейджи решений |
| Проверка/публикация | — | индикатор | список ошибок с переходом к блоку | зелёный шаг, следующее primary |

**Принцип 7. Ни одной плашки без выхода.** Каждое ошибочное/пустое состояние
обязано иметь явное действие (уже зафиксировано в коде Блока 1; контроль —
через тесты состояний).

## 6. Дизайн-токены

**Принцип 8. Цвета/состояния — через токены, не хардкод.** Наследие OL1
(`--graph-canvas-asis-opacity`) расширяется на рабочее место:
- `--ws-step-done/current/pending/na` (фон/текст/обводка step-bar);
- `--ws-primary`, `--ws-danger` (reject), `--ws-success` (accept/done);
- `--graph-canvas-trace-color` (хвост OL1-backlog: `#7b5cff` → токен);
- `--graph-canvas-asis-saturation` (хвост OL1-backlog).
Определения — в `styles/tokens.css` (светлая/тёмная темы), компоненты
ссылаются на переменные. Контраст пар текст/фон — ≥ 4.5:1 (приоритет 1
дисциплины).

## 7. Что НЕ меняется (ограждения)

Хост-канвас bpmn.io (версии, экспорты, XML E7, Validation E6), overlay OL1
(z-order, hit-testing, раскладка), read-only AS IS (md5-инвариант), RBAC,
i18n (все новые строки — через словарь ru/en).

## 8. План реализации (после апрува концепта)

1. Переключатель режимов «Схема | TO BE» + скрытие аналитических элементов
   в TO BE-режиме (App.jsx + точечный CSS).
2. Точка входа «Создать/Открыть TO BE» на экране «Схема» (одно primary +
   вторичные).
3. Левая панель TO BE-режима (§4).
4. Токены (§6) + перенос step-bar/кнопок/слоёв на них.
5. Tooltip причин недоступности шагов.
6. Скрины до/после всего пути технолога; полный прогон на stage EXIT=0.

   (текущее поведение W4) или вход всегда явный (только по кнопке)?

   данные stage (отдельной операцией) или только фильтруем в UI?

   (уже есть) или нужен кастомный (задержка, форматирование)?
