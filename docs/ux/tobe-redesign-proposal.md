## 4. Целевая компоновка рабочего места — 7 шагов

Принцип (из P4): **шаг определяет центральную зону**, а не только подсветку хедера. Хедер-степпер — единый, кликабельный, с доступностью (done ✓ кликабелен назад; current; pending — кликабелен, если данные позволяют, иначе title-причина). LLM-блоки (SchemaAssistantBlock/LlmAnalysisBlock) — в статусной зоне/панели соответствующего шага, сами блоки не трогаем.

Общий каркас (все шаги):

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Степпер: ✓Импорт → 2Трансформация → … → 7Пилот   [статус · версия · ●]  │
├──────────────────────────────────────────────────────────────────────────┤
│ Тулбар шага: [PRIMARY действие шага] [вторичные…]        [overflow ⋯]    │
├──────────────────────────────────────────────────────────────────────────┤
│ Статусная зона (0–1 строка, collapsible): баннеры/LLM-подсказки          │
├───────────────────────────────────────────────┬──────────────────────────┤
│                                               │ Инспектор (3 группы):    │
│          ЦЕНТРАЛЬНАЯ ЗОНА ШАГА                │ Объект / Процесс /       │
│          (зависит от шага, см. ниже)          │ Запуск — accordion       │
│                                               │ (вкладки как саб-табы)   │
└───────────────────────────────────────────────┴──────────────────────────┘
```

### Шаг 1. Импорт AS IS
```
Центр: превью AS IS (канвас read-only, fit) + карточка отчёта импорта
       (узлы/потоки/замечания-сводка по правилам)
Главное действие: [Загрузить BPMN] / [Взять из сессии ProcessMap] → «К трансформации»
Инспектор: «Процесс»→Замечания (группы по правилу, бейдж «Импорт»)
```
### Шаг 2. Трансформация
```
Центр: overlay-канвас (AS IS подложка + TO BE) + панель решений рядом:
       список решений trace_map (принять/отклонить) с подсветкой узла
Главное действие: [Запустить AI-трансформацию] → принять решения → «В конструктор»
LLM: SchemaAssistantBlock доступен (explain-step по выделенному узлу)
Инспектор: «Процесс»→Решения
```
### Шаг 3. Конструктор
```
Центр: канвас TO BE на всю высоту (zoom/fit/minimap — Z1), палитра операций
Главное действие: редактирование схемы; [Сохранить] (dirty ●)
Инспектор: «Объект» (Шаг/Блок/Поток/Сущности) — дефолт
LLM: SchemaAssistantBlock (suggest-next — кандидаты из каталога)
```
### Шаг 4. Рецепт
```
Центр: ФОРМА РЕЦЕПТА во всю центральную зону (не сайд-панель!):
       блюдо/SKU/техкарта, привязка к шаблону, параметры
Главное действие: [Создать/сохранить рецепт] → «К проверке»
Пустое состояние: «Сначала сохраните шаблон в Конструкторе →» (ux_gaps G5)
```
### Шаг 5. Проверка
```
Центр: отчёт проверки: сводка (узлы/потоки/ошибки/предупреждения) +
       лента замечаний с группировкой (Z2) + «Проверка по кухням»
       канвас — миниатюра с подсветкой проблемных узлов (клик→фокус)
Главное действие: [Запустить проверку] → устранить → «К публикации»
```
### Шаг 6. Публикация
```
Центр: карточка публикации: что публикуется (версия шаблона, рецепт),
       diff версий, чек-лист готовности
Главное действие: [Опубликовать] (confirm) → «Создать пилот» (ux_gaps G7)
Инспектор: «Процесс»→Версии/История
```
### Шаг 7. Пилот
```
Центр: панель пилота во всю зону: кухни, прогресс, метрики/расход
       (chart: bullet charts для KPI пилота — база chart: «3–10 KPI
       side by side», доступность AAA, значения текстом)
Главное действие: [Создать пилот] / мониторинг
Пустое состояние: «Пилот создаётся из опубликованного рецепта →» (ux_gaps G8)
```

Навигация T2 (requestTobeExit/модал ухода), переключатель «Схема/TO BE», «← К сессии» — без изменений во всех макетах.

## 6. План зонных PR

Порядок (после правок владельца): **токены → Z0 → Z1 → Z2 → Z3 → Z4 → Z5-остаток**.
Зависимости: токены — база для всех зон (красим токенами, не сырыми hex); Z0 —
контрасты поверх токенов; Z4 зависит от Z3-групп инспектора; Z5-остаток — последним,
поверх стабильных зон.

### Шаг «Токены». `--pm-tobe-*` в styles/tokens.css — S
- **Scope:** блок `--pm-tobe-*` по §5 (цвета/типографика/spacing из MASTER.md) + Google
  Fonts @import Fira Sans/Fira Code с system-fallback. НИ ОДНОГО потребителя — только
  объявления. Мост-алиасы `--ws-step-*` НЕ трогаем в этом шаге.
- **НЕ входит:** применение токенов в компонентах (это делают зоны), удаление старых var.
- **Тесты:** source-тест наличия блока и значений; build зелёный; визуальных изменений = 0.
- **Приёмка:** tokens.css содержит `--pm-tobe-*`; рендер stage идентичен (скрин-контроль).

### Z0. Хотфикс контрастов (только значения цветов, без перестройки) — S
- **Scope:** ровно три точки, красим ТОКЕНАМИ:
  1. текст карточек замечаний `#EBF0F9` на белом (1.14:1) → `var(--pm-tobe-fg)` (16.7:1) —
     `.ctor-check__finding*` в `constructor/Constructor.css:548-573` + import-findings
     (`Workspace.jsx:1135-1148` стили);
  2. pending-степпер ~3.1:1 → `var(--pm-tobe-step-pending)` без opacity (≈7:1 на `#16202F`) —
     `WorkflowBar.css:44-47` + дубль `Workspace.css:61-63` (только color/opacity, структура та же);
  3. disabled-стейты зоны (тулбар-кнопки, вкладки) → контраст ≥4.5:1 токенами,
     opacity-гасящие заменяются цветом (`disabled-states` MD + `color-contrast`).
- **НЕ входит:** любая перестройка layout/DOM, title-подсказки (это Z5), новые компоненты.
- **Тесты:** контраст-guard source-тест (по образцу dark-theme contrast guard) на три пары;
  build; скрины до/после на stage (findings читаемы, pending читаем).
- **Приёмка:** три пары ≥4.5:1 замером; ни одного визуального изменения вне трёх точек.

### Z1. Канвас (высота / zoom / fit / minimap) — M
- **Scope:** убрать `max-height:620px` (`GraphCanvas.css`), канвас на всю `.ws__canvases`; контролы zoom ±/fit/1:1 в углу канваса; wheel-zoom (ctrl) + pan drag; minimap (viewBox-рамка) для моделей >50 узлов; контрастные стили AS IS-подложки сохранить; i18n-пробелы зоны (палитра STRUCTURAL_BLOCKS, `Workspace.jsx:50-55`).
- **НЕ входит:** смена SVG-рендера на bpmn-js; правки layout-алгоритма `computeViewBox`; редактирование drag&drop (S-механики #680 не трогаем).
- **Тесты:** source-тест (контролы в DOM, i18n-ключи); unit computeViewBox неизменен; ручной gate на stage: «Салат Греческий» 221 узел — fit показывает всю схему, zoom работает.
- **Приёмка:** SVG занимает ≥90% высоты `.ws__main`; fit/zoom контролы видны и работают; AS IS overlay OL1 цел (derived_from подсветка, read-only).

### Z2. Замечания (группировка, источник, клик→фокус) — M
- **Scope:** единая лента findings с бейджем источника (Импорт/Трансформация/Dry-run/Кухни); группировка по коду правила + счётчики + сворачивание; severity error/warning иконка+текст+цвет для ВСЕХ источников; клик→select+scrollIntoView для import-findings (как dry-run, `Workspace.jsx:508-520`); «показать ещё» >50 в группе (P9); i18n-пробелы зоны (тексты ленты/бейджей).
- **НЕ входит:** изменение самих правил проверок (v0.3); backend; структура `validation.findings`; **stale-счётчик замечаний НЕ трогаем** (пакет 1, домен трансформации — отдельный трек); цвет текста карточек уже починен в Z0, здесь не дублируем.
- **Тесты:** unit на группировщик (view-mapper, как llmAnalysisView); source-тесты бейджей/severity; i18n.
- **Приёмка:** каждая карточка читаема (контраст ≥4.5:1), имеет бейдж источника; клик по любой — фокус узла на канвасе; 190 findings не вешают панель.

### Z3. Панель параметров (progressive disclosure) — M
- **Scope:** 11 вкладок → 3 группы (Объект/Процесс/Запуск) с саб-табами/accordion; дефолтная группа по контексту (выделен узел → Объект; после проверки → Процесс→Замечания); **рефактор-дедуп panel body** (P8) в один компонент без смены поведения.
- **НЕ входит:** переработка содержимого вкладок (формы как есть); RecipePanel/PilotPanel — их переезд в центр делает Z4, здесь только группировка.
- **Тесты:** существующие `stepStates.test.mjs` и профильные тесты панели зелёные; source-тест групп; i18n.
- **Приёмка:** видно ≤3 группы + саб-табы активной группы; любая старая вкладка достижима ≤2 кликов; ничего не удалено.

### Z4. Шаг ↔ рабочая область — L
- **Scope:** степпер кликабелен (done/current/pending-доступные); step → центральная зона по §4 (Рецепт/Проверка/Публикация/Пилот — полноценные центры вместо сайд-панели); guard'ы доступности (нет шаблона → шаг «Рецепт» с title-причиной и CTA в Конструктор); глубокие ссылки `?step=` (deep-linking).
- **НЕ входит:** мастер-визард «Новый процесс» (ux_gaps 4.1 — отдельный эпик); изменение T2-навигации ухода; RBAC.
- **Тесты:** unit маппинга step→zone; source-тесты guard'ов; e2e-probe на stage (клик по шагам).
- **Приёмка:** клик по «Рецепт» показывает форму рецепта в центре; недоступный шаг объясняет почему (`empty-nav-state`); «Схема/TO BE» и модал ухода целы.

### Z5-остаток. Хедер / тулбар / accessibility — S
- **Scope:** title-подсказки и disabled-причины на всех кнопках тулбара (P6); дедуп баннеров → статусная строка (P7); удаление сайдбар-дубля степпера; применение `--pm-tobe-*` в `.ws*` для ещё не покрытых raw hex (мост `--ws-step-*` → алиасы); фокус-ринги 2px `--pm-tobe-secondary`; i18n-задолженности зоны (P10: `Workspace.jsx:638-649`, `App.jsx:3773-3776`).
- **НЕ входит:** рестайл тёмного shell приложения; TopBar проекта; смена темы; значения контрастов (уже Z0), сами токены (уже шаг «Токены»).
- **Тесты:** контраст-guard source-тест на новые пары; i18n source-тест; build.
- **Приёмка:** у каждой тулбар-кнопки title; hover 150–300ms, cursor-pointer, фокус виден; контрасты степпера/тулбара ≥4.5:1.

Каждый PR: дельта pytest/node --test = 0 к baseline, `npm run build` зелёный, чек-лист §7, скрины до/после в `docs/ux/`.
