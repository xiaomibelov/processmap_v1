# E9.4 — Контракт метрик пилота (САУ РТК)

Источник данных: **САУ РТК** (система автоматического управления
робототехническим комплексом пилотной кухни). В MVP ввод ручной —
`POST /api/sku-bindings/{id}/metrics`; контракт ниже фиксирует формат,
в котором САУ РТК будет отдавать те же данные при автоматизации.

## Сущность: `pilot_metric_sample`

Одна выборка = один отчётный интервал на пилотной кухне по одной привязке.

| Поле | Тип | Описание |
| --- | --- | --- |
| `binding_id` | uuid, FK → `sku_binding.id` | привязка SKU в статусе `pilot` |
| `ts` | timestamp, default `now()` | момент фиксации выборки (ставит backend; САУ РТК передаёт время окончания интервала при интеграции) |
| `orders_count` | int ≥ 0 | количество заказов (порций), выполненных за интервал |
| `critical_errors` | int ≥ 0 | критические ошибки выполнения (аварийная остановка РТК, отклонение температуры за критические границы, нарушение последовательности операций) |
| `defect_count` | int ≥ 0 | заказы с браком (не прошли контроль качества), ⊆ `orders_count` |

Производная метрика (не хранится): `defect_rate_pct = defect_count / orders_count * 100`
(0 при отсутствии заказов).

## Частота

- **MVP (ручной ввод):** 1 выборка в конце каждой производственной смены
  пилотной кухни (1–3 раза в сутки).
- **Целевая интеграция САУ РТК:** push раз в 15 минут или по событию
  «конец интервала» — тот же формат тела, те же правила валидации.

## Источник и ответственность

- Источник: телеметрия САУ РТК пилотной кухни (`pilot_kitchen_id`).
- MVP-ввод: технолог/аналитик пилота (роли `analyst`/`admin`).
- Выборки принимаются только пока привязка в статусе `pilot` (иначе 409).

## API

`POST /api/sku-bindings/{id}/metrics` (analyst/admin):

```json
{ "orders_count": 14, "critical_errors": 0, "defect_count": 0 }
```

Ответ `201` — сохранённая выборка. Отрицательные значения → `422`.

## Прогресс и критерии выхода

`GET /api/sku-bindings/{id}/pilot-metrics` возвращает агрегат всех выборок
против `pilot_exit_criteria_json`:

- `min_orders`: Σorders_count ≥ порога;
- `max_critical_errors`: Σcritical_errors ≤ порога;
- `max_defect_rate_pct`: Σdefect_count / Σorders_count × 100 ≤ порога.

Rollout (`POST /{id}/rollout`) разрешён только при `all_met = true`,
иначе `409` с перечнем невыполненных критериев
(«min_orders не выполнен: 14/20»).
